# WukongAutoBench

Консольный инструмент на C# (.NET 8) для локального автоматического прогона **Black Myth: Wukong Benchmark Tool** (Steam, App ID 3132990) в двух режимах:

1. **CPU-тест** – нагрузка на процессор, влияние видеокарты сведено к минимуму;
2. **GPU-тест** – максимальная нагрузка на видеокарту.

Одна команда: инструмент сам находит бенчмарк, пишет настройки, запускает его, проходит меню, дожидается конца каждого прохода, разбирает результаты и выводит отчёт (характеристики ПК, результаты обоих тестов и использованные настройки). Исходные настройки бенчмарка после прогона возвращаются.

## Быстрый старт

Требования:

- Windows 10/11 x64;
- [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) (для сборки) или .NET 8 Runtime (для готового exe);
- Steam с установленным Black Myth: Wukong Benchmark Tool (бесплатный);
- запускать бенчмарк вручную заранее не нужно: если `GameUserSettings.ini` ещё нет, инструмент сам один раз запустит бенчмарк, дождётся, пока тот создаст настройки, и закроет его штатно. Первый прогон из-за компиляции шейдеров идёт дольше, таймаут проходов на это время автоматически увеличивается на 10 минут.

```powershell
git clone <ссылка на репозиторий>
cd WukongAutoBench
dotnet run -c Release --project src/WukongAutoBench
```

Или собрать exe и запускать его:

```powershell
dotnet publish src/WukongAutoBench -c Release -r win-x64 --self-contained false -o publish
.\publish\WukongAutoBench.exe
```

Прогон занимает около 6-10 минут. **Во время прогона не трогайте мышь и клавиатуру**: бенчмарк не умеет стартовать тест из командной строки, поэтому инструмент сам нажимает кнопки его меню.

Отчёт печатается в консоль и сохраняется в `results\<дата_время>\`:

| Файл | Что внутри |
|---|---|
| `report.md` | отчёт целиком: железо, результаты, настройки, обоснование |
| `report.json` | то же в машиночитаемом виде (для сравнения прогонов) |
| `cpu_result.json`, `gpu_result.json` | исходные файлы результатов от Benchmark Tool |
| `run.log` | лог прогона |
| `screens\` | уменьшенные снимки окна игры на шагах прохода меню (BMP), для разбора неудачных прогонов |

### Команды и параметры

```
WukongAutoBench.exe [run]        оба прохода и отчёт (по умолчанию)
WukongAutoBench.exe inspect      что найдено: пути, текущие настройки, характеристики ПК; ничего не запускает
WukongAutoBench.exe run --dry-run   записать «как будет» конфиги в папку отчёта, бенчмарк не трогать
WukongAutoBench.exe report --cpu <файл> --gpu <файл>   собрать отчёт из сохранённых результатов
```

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `--only cpu\|gpu` | оба | один проход |
| `--cpu-scale <10..100>` | 25 | масштаб рендеринга в CPU-тесте, % |
| `--gpu-scale <50..200>` | 100 | масштаб рендеринга в GPU-тесте, % |
| `--gpu-rt` / `--no-gpu-rt` | авто | принудительно включить / выключить трассировку лучей в GPU-тесте; по умолчанию включается на NVIDIA RTX |
| `--install-dir <путь>` | из Steam | папка бенчмарка, если автопоиск не справился |
| `--launch steam\|direct` | steam | запуск через `steam.exe -applaunch` или напрямую exe |
| `--timeout <мин>` | 15 | таймаут одного прохода |
| `--start-button x,y` / `--confirm-button x,y` | 0.11,0.45 / 0.39,0.585 | координаты кнопок меню в долях окна |
| `--render-height <px>` | из конфига | высота окна, если её нет в конфиге |
| `--keep-config` | выкл. | не возвращать исходные настройки |
| `--out <путь>` | `results` рядом с exe | куда писать отчёты |

Коды возврата: `0` – оба прохода успешны, `2` – хотя бы один проход упал (отчёт всё равно пишется), `1` – ошибка до запуска (не найден Steam/бенчмарк/конфиг, неверные параметры).

## Выбор настроек

Настройки Benchmark Tool хранятся в `<папка бенчмарка>\b1\Saved\Config\Windows\GameUserSettings.ini` в двух представлениях, и инструмент меняет оба согласованно:

- строка `UISettingData=(("Key", "Value"),...)` – значения меню игры (шкала качества 1-5);
- секция `[ScalabilityGroups]` – группы качества Unreal Engine (`sg.*`, та же шкала 0-4) и `sg.ResolutionQuality` – масштаб рендеринга в процентах.

Разрешение окна **не меняется**: каждый проход строится от исходного конфига пользователя, меняется только то, что перечислено ниже. Нужное соотношение нагрузки даёт масштаб рендеринга, а подставлять разрешение, которого может не быть у монитора проверяющего, рискованно.

### CPU-тест: нагрузка на процессор, влияние видеокарты минимально

| Настройка | Значение | Зачем |
|---|---|---|
| Масштаб рендеринга | **25%** | при 25% видеокарта считает в 16 раз меньше пикселей; время кадра на GPU падает до единиц мс и перестаёт ограничивать FPS |
| Тени, глобальное освещение, отражения, постобработка, эффекты, материалы, растительность, сглаживание, текстуры | **минимум (1)** | это работа почти исключительно для GPU |
| Дальность прорисовки | **максимум (5)** | больше объектов в сцене = больше отсечения, анимации и draw calls, то есть работы для процессора. Здесь сознательно нагружаем CPU, а не только «снимаем» нагрузку с GPU |
| Генерация кадров | выкл. | дорисовывает кадры без участия процессора и завысила бы результат |
| VSync, ограничение FPS | выкл. | иначе FPS упрётся в частоту монитора, а не в скорость CPU |
| Трассировка лучей, размытие в движении | выкл. | чистая нагрузка на GPU |

### GPU-тест: максимальная нагрузка на видеокарту

| Настройка | Значение | Зачем |
|---|---|---|
| Масштаб рендеринга | **100%** | каждый пиксель окна считается без понижения внутреннего разрешения (можно поднять до 200% через `--gpu-scale`) |
| Все группы качества и дальность | **максимум (5, «кинематографическое»)** | самые тяжёлые тени, освещение, отражения, растительность и постобработка |
| Генерация кадров | выкл. | вставляет кадры, которые GPU не рендерил полностью, FPS перестаёт отражать производительность |
| VSync, ограничение FPS | выкл. | иначе видеокарта простаивает в ожидании обновления экрана |
| Трассировка лучей | вкл. на NVIDIA RTX, иначе выкл. (`--gpu-rt` / `--no-gpu-rt` меняют выбор) | RT – самая тяжёлая для видеокарты часть кадра. Полная трассировка в Black Myth: Wukong сделана в первую очередь под NVIDIA; на картах без аппаратного RT бенчмарк может упасть, а на AMD/Intel её поведение не проверено, поэтому там она включается только вручную |

Апскейлер (`SuperResolutionSampling`) не меняется: внутреннее разрешение задаёт масштаб рендеринга, а при 100% апскейлер ничего не понижает.

### Как проверяется, что настройки сработали

Инструмент не верит конфигу на слово, а проверяет результат:

- **сверка настроек**: в файле результата бенчмарк пишет, с какими настройками реально шёл прогон (`QualityLevel`, `ImageQuality`, `Rtx`, `InsertFrame` ...). Если значения разошлись с запрошенными, в отчёте будет предупреждение;
- **кто ограничивал кадр**: в `Records` для каждого замера есть время кадра на CPU и на GPU. Отчёт считает долю замеров, где кадр ограничен процессором, и пишет вердикт: в CPU-тесте эта доля должна быть высокой, в GPU-тесте низкой. Если в CPU-тесте видеокарта всё ещё влияет, отчёт подскажет уменьшить `--cpu-scale`;
- **загрузка**: средняя загрузка CPU/GPU по данным бенчмарка, плюс собственный замер инструмента (CPU через `GetSystemTimes`, GPU через `nvidia-smi`, если он есть).

## Что в отчёте

- **Характеристики ПК**: процессор (модель, ядра/потоки, частота, L3), видеокарты (модель, объём VRAM, драйвер, режим дисплея), оперативная память (объём, модули, частота), ОС и сборка, материнская плата, накопители, схема питания Windows (влияет на результат), версия бенчмарка; плюс то, что бенчмарк сам записал о системе.
- **Результаты обоих тестов** (из файла Benchmark Tool): средний / минимальный / максимальный FPS, FPS95 («Low 5%» на экране бенчмарка), загрузка CPU и GPU, видеопамять. По покадровым записям `Records` дополнительно считаются медиана, 1% и 0.1% low, время кадра (среднее и 99-й перцентиль), время кадра отдельно на CPU и GPU.
- **Настройки каждого теста**: что записано, какое было значение до этого и что бенчмарк фактически применил, с объяснением выбора.

## Как устроен автоматический сценарий

1. **Поиск бенчмарка** без захардкоженных путей: реестр Steam (`HKCU\Software\Valve\Steam`) → `steamapps\libraryfolders.vdf` (все библиотеки, включая другие диски) → `appmanifest_3132990.acf` (папка установки и build id).
2. **Первый запуск**, если `GameUserSettings.ini` ещё нет: инструмент запускает бенчмарк, ждёт (до 5 минут), пока в конфиге появится строка `UISettingData`, и закрывает игру сообщением `WM_CLOSE` (как крестик окна): при штатном выходе игра сохраняет настройки. Если не закрылась за минуту – принудительно.
3. **Резервная копия** `GameUserSettings.ini`. Если прошлый запуск был прерван и копия осталась, сначала восстанавливается оригинал.
4. **Для каждого прохода**: исходный конфиг + настройки профиля → запись (кодировка и формат файла сохраняются, меняются только нужные ключи).
5. **Экраны первого запуска**: пока игра не настроена, при каждом старте она показывает выбор яркости, языка и соглашение о конфиденциальности вместо главного меню. Инструмент отмечает в конфиге прохода, что первичная настройка пройдена (`FirstSettingFinish=True`, `PrivacyAgreement=1`, `AgreementReaded=1`, то есть соглашение принимается от имени пользователя, яркость и язык остаются по умолчанию). После прогона исходный конфиг возвращается.
6. **Запуск** через `steam.exe -applaunch 3132990` (бенчмарк проверяет владение через Steam); повторные попытки тоже идут через Steam, и перед каждой настройки прохода записываются заново: при выходе игра перезаписывает конфиг.
7. **Меню**: бенчмарк не имеет ни ключей командной строки, ни API для старта теста, поэтому инструмент проходит меню эмуляцией ввода (`SendInput`), но не вслепую по таймеру, а глядя на экран. Он находит окно процесса `b1-Win64-Shipping.exe`, выводит его на передний план и раз в 2 секунды снимает клиентскую область окна (GDI `BitBlt`):
   - экран чёрный (идёт загрузка) – ничего не нажимает;
   - на экране заставка «Нажмите любую кнопку» – кликает в пустую часть окна, каждый третий раз нажимает Enter;
   - на двух снимках подряд видно главное меню (распознаётся по светлому тексту пункта «Выйти» слева) – кликает «Тест быстродействия» → «Подтвердить» и проверяет, что меню исчезло. Если меню осталось, нажимает ещё раз; если меню не распознано за 2 минуты (другое оформление), нажимает кнопки по координатам.

   После старта теста до 6 минут ничего не нажимает, чтобы не мешать замеру; если результат так и не появился, проходит меню ещё раз. Координаты кнопок заданы в долях клиентской области, поэтому от разрешения не зависят; приложение DPI-aware, поэтому масштабирование Windows не сбивает клики. Ввод отправляется, только если в фокусе именно окно бенчмарка. Снимки ключевых шагов сохраняются в `screens\` папки отчёта: по ним видно, на каком экране остановился неудачный проход.
8. **Ожидание результата**: после прохода бенчмарк пишет JSON (без расширения, имя – unix-время старта) в `%TEMP%\b1\BenchMarkHistory\Tool\`. Инструмент запоминает, какие файлы были до запуска, и берёт только новый файл, когда он дописан и разбирается как JSON.
9. **Закрытие** процесса принудительно: при штатном выходе игра перезаписывает `GameUserSettings.ini` и могла бы помешать восстановлению настроек.
10. После обоих проходов (а также при ошибке и по Ctrl+C) исходный конфиг возвращается и проверяется побайтно.

Если процесс бенчмарка упал без результата, проход перезапускается (до 3 попыток в рамках таймаута). Если один проход не удался, второй всё равно выполняется, а отчёт показывает, что получилось.

## Структура

```
src/WukongAutoBench/
  Program.cs                 команды run / inspect / report, сценарий прогона
  Options.cs                 параметры командной строки
  Steam/                     парсер VDF/ACF и поиск установки
  Config/IniDocument.cs      точечное редактирование GameUserSettings.ini (в т.ч. UISettingData)
  Config/BenchmarkProfile.cs профили CPU- и GPU-теста и обоснование настроек
  Config/ConfigGuard.cs      резервная копия и восстановление настроек
  Running/                   запуск, окно и ввод (WinAPI), ожидание результата, замер загрузки
  Results/                   разбор результата и статистика по Records
  Hardware/SystemInfo.cs     характеристики ПК (CIM через PowerShell, реестр, WinAPI)
  Reporting/                 отчёт: консоль, Markdown, JSON
tests/WukongAutoBench.Tests/ тесты парсеров, профилей, восстановления конфига, отчёта
```

Внешних NuGet-пакетов нет: только стандартная библиотека .NET и WinAPI.

## Тесты

```powershell
dotnet run --project tests/WukongAutoBench.Tests
```

26 тестов, Steam и игра не нужны: поиск библиотек Steam, правка INI в UTF-8 и UTF-16 без побочных изменений, применение профилей, отметка первичной настройки игры, разбор результата и статистика, ожидание недописанного файла, восстановление конфига после сбоя, сверка применённых настроек (в том числе пресет «пользовательский» и уровень трассировки), автовыбор трассировки лучей, распознавание главного меню и чёрного экрана по снимку, сборка отчёта. Файл результата в `Fixtures` синтетический, но повторяет формат, который пишет бенчмарк.

## Ограничения

- Работает только в Windows: Benchmark Tool – Windows-приложение, меню проходится через WinAPI. Команда `report` работает на любой ОС.
- Главное меню распознаётся по снимку экрана, но сами кнопки нажимаются по координатам. Если в новой версии бенчмарка кнопки переедут, координаты меняются параметрами `--start-button` / `--confirm-button` без пересборки.
- Окно игры должно быть видно на экране (не свёрнуто и не перекрыто): снимок берётся с экрана, а не из видеопамяти игры.
- Если игра закрывается на загрузке с кодом 3, это сбой драйвера видеокарты, а не инструмента: в системном журнале Windows в тот же момент появляется событие `nvlddmkm` 153 (или LiveKernelEvent 141). Инструмент перезапускает проход до 3 раз; если игра падает каждый раз, обновите драйвер видеокарты и проверьте целостность файлов бенчмарка в Steam. На проверочном ПК (RTX 3060) с драйвером 572.83 GPU-тест падал на каждом запуске, после обновления до 617.42 оба теста прошли.
- Если бенчмарк запущен от администратора, а инструмент нет, Windows не пропустит ввод (UIPI) – запускайте оба с одинаковыми правами.
- Если бенчмарк установлен в `Program Files`, для записи конфига может понадобиться консоль от имени администратора.
- Ключ, которого нет в `UISettingData` этой версии бенчмарка, не добавляется (неизвестное значение может уронить игру), а отмечается в отчёте.
